# AGENTS.md

## Purpose

`interrail-to-calendar` turns a trip shared from the Interrail/Eurail **Rail Planner** app
("share as a link", e.g. `https://eurailapp.com/share/trip?id=<UUID>&type=list&brand=interrail`)
into calendar events. The user pastes the link, sees every travel in the trip grouped by day,
selects legs (individually, per travel, or per whole day), and downloads an `.ics` file with
**one event per train leg**.

## Stack & commands

- [Fresh 3](https://next.usefresh.dev/) (alpha, `@frsh/fresh` aliased as `fresh`) on **Vite 8**, **Preact 11**, `@preact/signals`.
- Package manager: **npm** (keep `package-lock.json`).
- Node ≥ 26 (native `Temporal` is used on the server and in tests).

| Command           | What it does                     |
| ----------------- | -------------------------------- |
| `npm run dev`     | Vite dev server                  |
| `npm run build`   | Production build (`.output/`)    |
| `npm run preview` | Serve the production build       |
| `npm test`        | Run unit tests (vitest)          |

## Fresh 3 conventions

- File-system routes live in `routes/`. Each route imports **generated, typed helpers** from a sibling
  `./$<route>.ts` module (e.g. `routes/trip.tsx` → `import { handler, page } from "./$trip.ts"`).
  These are generated into `.fresh/types/` (gitignored, regenerated by the Vite plugin on dev/build).
- Server data loading:
  ```tsx
  export const handlers = handler({
    async GET(ctx) {            // ctx.req, ctx.url (parsed URL), ctx.params
      return { data: { ... } }; // or return a Response
    },
  });
  export default page(function Page({ data, url }) { ... });
  ```
- `routes/_app.tsx` uses `app(...)` from `./$_app.ts` and is the HTML shell.
- **Islands** (`islands/`) are the only components hydrated on the client. Their props must be
  serializable (plain JSON-like data; no class instances, no `Temporal` objects).
- `components/` are server-rendered only (unless imported by an island).

## Data source: the share link

No API / app reverse-engineering is needed: `GET https://eurailapp.com/share/trip?id=<UUID>&type=list&brand=interrail`
returns an HTML page with the whole trip inlined as a script:

```html
<script>
  payload = {"name":"Test trip","travels":[...],"version":1,"brand":"interrail","pass":false}
```

- **CORS blocks fetching it from the browser** (no `Access-Control-Allow-Origin`; preflight returns 403),
  so it is always fetched **server-side**. Extract with a regex and `JSON.parse` — never `eval`.
- Only ever fetch `https://eurailapp.com/share/trip?id=<UUID>` with a validated UUID (no arbitrary URLs → no SSRF).
- The app's "share" action yields text, not just a URL: `Check out my European rail trip: <url>`.
  `parseShareUrl` extracts the URL from free text (a bare UUID is accepted too).
- A captured example lives in `test/fixtures/share-trip.html`.

### Payload shape

`infoJson` / `optionsJson` fields are **JSON-encoded strings** and need a second `JSON.parse`.

```ts
payload: { name: string; travels: Travel[]; version: number; brand: "interrail" | "eurail"; pass: boolean }

Travel: {
  id: string; tripId: string; type: number; // 0 = planned in the app, 1 = inserted manually
  date: "2026-12-24T00:00:00.000Z";       // date only, midnight Z
  from: string; to: string;                // station names
  infoJson: string; // { date:{day,month,year}, departureTime:{hours,minutes,offset}, arrivalTime:{...}, ctxRecon, ... }
  optionsJson: string; // { departure:Station, arrival:Station, dateSince1970: <UTC ms of first departure>, firstClass, ... }
  legs: { sortOrder: number; infoJson: string /* LegInfo */ }[];
}

LegInfo: {
  type?: "TRAIN_TRAVEL" | "STATION_CHANGE_PUBLIC_TRANSPORT" | "CHKI"; // train | transfer | check-in (e.g. Eurostar)
                              // missing on manually inserted trains (dataSource: 0, stationId: 0) → treat as train
  trainName: string;          // "ICE 121", "" for non-trains
  transportType?: string;     // "ICE", "IC", ...
  startTime, endTime, duration: { hours, minutes, offset /* always 0 */ };
  departureTrack?: string; arrivalTrack?: string;
  directionStation: string;
  operator?: { admin: string; adminName: string };
  trainStopStations: { name, country, stationId, coordinates:{latitude,longitude} }[]; // first = origin, last = destination
  stopExtraInfo?: { index, arrivalTime, departureTime }[];
  attributes: Record<string, string>; isSeparateTicket: boolean;
}
```

### Time rules (important)

- All `hours/minutes` are **wall-clock local time of the station** they refer to (`offset` is always 0).
  E.g. Eurostar Lille Europe 13:35 → London St Pancras 13:57 (= 12:35Z → 13:57Z).
- Timezone is derived from the station's `country` (`lib/timezones.ts`); fallback uses `optionsJson.dateSince1970`.
- Legs carry no date: start from the travel's `infoJson.date` and roll forward a day whenever a time goes
  backwards (overnight trains).
- Use `Temporal` for all date/time math; emit UTC (`...Z`) in the `.ics`.

### Merging legs of the same train

One ride is sometimes split over two travels (e.g. EC 11 Arth-Goldau → Chiasso, then Chiasso → Milano).
`findContinuations` flags a train leg that has the same name as the previous train leg, departs from the
station it arrived at, within 60 min. The island shows a per-leg "Same event as …" toggle (off by default);
`mergeLegs` folds toggled legs into the previous one before `buildIcs` (UID `<keyA>+<keyB>`).


## Conventions

- TypeScript everywhere, Preact (not React) APIs, signals for island state.
- Use `Temporal`, never `Date`, on both server and client. Normalized data passed to islands uses ISO strings.
  Client code must `import "../lib/temporal.ts"` (first) before using `Temporal`: it loads `temporal-polyfill`
  via a dynamic import only when `globalThis.Temporal` is missing (e.g. Safari), so browsers with native
  support never download it.
- Avoid runtime dependencies unless clearly needed.
- Run `npm test` and `npm run build` before considering a change done.
